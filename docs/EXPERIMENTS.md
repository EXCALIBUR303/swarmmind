## Calibration (Phase 3)

**Method** (§20.6): for each level, evaluate the Random policy and the
greedy nearest-frontier reference heuristic on that level's frozen
**validation** set (50 procedurally generated maps, seeds
1,000,000–1,000,049). `max_steps(level) = round_up_to_10(3 × P90(heuristic
completion steps))`, bounded below by the provisional value chosen in
Phase 0/1 if that is larger. Random success on L2 must stay below 0.6 or
the level needs adjusting (§20.6); the heuristic's success rate must reach
≥ 0.95 within the resulting `max_steps` or the level/heuristic needs
revisiting.

**Result: every level's Phase 0/1 provisional `max_steps` already exceeds
what the calibration formula requires, so no level's `max_steps` changed.**
The provisional values become each level's calibrated value, to be frozen
as-is in Phase 6.

| Level | `max_steps` (unchanged) | Heuristic P90 steps | Formula floor (3×P90, rounded up to 10) | Heuristic success | Random success | Random censored-mean steps |
|---|---|---|---|---|---|---|
| L1 | 100 | 17.1 | 60 | **1.000** | 0.58 | 71.48 |
| L2 | 150 | 21.0 | 70 | **1.000** | 0.54 | 116.58 |
| L3 | 200 | 28.2 | 90 | **1.000** | 0.38 | 167.90 |
| L4 | 200 | 60.0 | 180 | **1.000** | 0.26 | 180.06 |

(50 validation-map episodes per cell, 1 episode/map, evaluation sampling
seed derived per-map; generated by `scripts/evaluate.py --split validation`.)

**Gate checks:**
- Heuristic success ≥ 0.95 at every level within its `max_steps`: **PASS** (all 1.000).
- Random success on L2 < 0.6: **PASS** (0.54).
- No level required a density/target-count adjustment.

**A note on reproducibility:** the first calibration pass used Python's
built-in `hash()` to derive per-episode evaluation seeds in
`scripts/evaluate.py`, which is randomized per-process (`PYTHONHASHSEED`)
and produced different Random-policy numbers on every run — a
reproducibility bug in the *script*, not the environment. Fixed by
deriving seeds from `sha256` instead; the table above reflects the fixed,
now-stable numbers (confirmed identical across repeated runs).

**A note on the heuristic itself:** the first calibration pass surfaced two
genuine bugs in the reference heuristic (fixed in this phase, see
`docs/phase_reports/PHASE_3.md`): (1) two robots' independent plans could
permanently deadlock by repeatedly targeting the same destination cell,
and (2) a robot's plan could target a cell a *different*, not-yet-processed
robot still physically occupied, which the environment's own R1 rule
always blocks regardless of what that occupant does — producing the same
kind of permanent standoff. Both are fixed by resolving each robot's
ranked candidate list sequentially against a set of already-claimed/
currently-occupied destination cells, plus a light anti-backtrack
tie-break to prevent 2-step oscillations. These fixes are internal
bookkeeping for a hand-coded reference tool (§14.2) and do not touch the
environment's own symmetric, index-independent conflict rule (§6.5), which
is unchanged.

## Phase 4 learning-gate thresholds (derived)

- **Final validation success rate** ≥ `max(0.85, random_success + 0.25)` = `max(0.85, 0.58 + 0.25)` = `max(0.85, 0.83)` = **0.85**
- **Censored mean steps** ≤ `0.7 × random_censored_mean_steps` = `0.7 × 71.48` = **50.0**

clear them, per the spec's Phase 4 validation gate).
